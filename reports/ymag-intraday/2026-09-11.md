## Data/validation note — flagged for routine maintainer

`ROUTINES.md`'s pre-commit validation list states that `cumulative_realized_gain`
must not be negative, alongside cash/share fields where that constraint is
correct. This is inconsistent with the strategy design: TRIM_STOPLOSS,
TRIM_MARKET_TREND, TRIM_MAG7_BREADTH, and EXIT_BREAKDOWN are all
defensive/loss-cutting actions expected to fire during price weakness, when
selling below avg_cost (a realized loss) is a normal, even likely, outcome.
Today's TRIM_MARKET_TREND realized -$0.022124, correctly reflecting a sale
slightly below avg_cost. Treating this as a hard validation failure would
block every future loss-taking trim from ever committing. This run treated
the negative value as legitimate and committed it (all other validation
checks passed cleanly), but the validation rule itself should be corrected
to only require non-negative on `cumulative_dividends`,
`cumulative_dividend_cash_in`, `cumulative_sale_cash_in`, cash/share
fields, and `total_account_value` — not `cumulative_realized_gain`.
